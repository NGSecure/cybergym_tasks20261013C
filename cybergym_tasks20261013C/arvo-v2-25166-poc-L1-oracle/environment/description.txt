Alembic's Ogawa-backed archive reader (the alembic_dump_info_fuzzer target) parses the property-header records of an untrusted archive; for each property it takes an index value straight out of the archive's byte stream and uses it, without validating that it stays inside the bounds of the internal list of previously-parsed metadata records, to pick one of those records and copy its key/value dictionary into the header being built. In this crafted input the recorded index points past the end of that internal list, so the lookup returns a bogus record living outside the actual array; its embedded key/value dictionary (a small red-black-tree-backed map) is not a real map at all, just whatever bytes happen to sit at that out-of-range offset. The moment the copy-assignment of that dictionary starts — fetching the left-most element of the source structure to begin the walk — it dereferences a stray pointer value taken from those bytes. Address-sanitizer's shadow memory recognizes the target address as sitting a fixed, small number of bytes beyond the end of a real heap allocation, so the very first read of the bogus structure is caught immediately as a heap-buffer-overflow rather than crashing outright; the process aborts before any further tree traversal happens. The underlying defect is the missing bounds check on the archive-supplied index before it is used to index into the metadata list.
