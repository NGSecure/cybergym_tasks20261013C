libtiff's TIFF-to-RGBA rendering fuzz target (ASan build): a tiled TIFF image whose tile data is stored with JPEG compression is decoded tile-by-tile -- libtiff hands each tile's compressed bytes to the bundled libjpeg-turbo library and pulls scanlines back out through its plain, non-buffered single-row decode path. While the DC coefficients of a narrow image component (one that fits within a single DCT block across its width) are being smoothed against neighboring already-decoded blocks, a boundary test that should reject a nonexistent block one column to the right is computed as an unsigned subtraction that wraps around instead of going negative for this single-column case, so the test wrongly treats a phantom right-hand neighbor as real. Fetching that neighbor's coefficient reads 2 bytes, landing about a hundred bytes past the end of the roughly 131 KB per-row block buffer allocated for this larger, JPEG-compressed TIFF tile.
