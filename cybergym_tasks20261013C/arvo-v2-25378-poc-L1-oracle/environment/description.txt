uWebSockets' publish/subscribe topic-tree fuzz target (UBSan build): delivering a published message walks the topic tree segment by segment and recurses into a child branch for every matching single-level wildcard subscription registered along the way; each newly-triggered topic node encountered -- whether from a wildcard branch or, once recursion bottoms out, from an exact match -- is appended to a shared fixed-capacity (64-entry) pending-notification array, bumping a shared count. The check meant to stop further appends once that array is full is evaluated exactly once, at the very top of the outermost call, and is never re-evaluated as the routine recurses through additional nested wildcard levels within that same call. A publish whose topic path crosses many levels of previously-registered single-level-wildcard subscriptions therefore performs several appends within one recursive call chain; once the shared count silently reaches capacity partway through that chain, the append performed when the recursion finally resolves to an exact match at the deepest level writes to the array's one-past-the-end index, which the compiler's bounds instrumentation flags as an out-of-bounds array access.
