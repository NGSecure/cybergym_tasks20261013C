Skia's SkRuntimeEffect / SkSL shader-compiler fuzz target (ASan build): parsing an SkSL program whose top-level statement is a discarded expression containing a postfix increment/decrement operand crashes with a wild-pointer read segfault while the compiler's control-flow-graph-based peephole optimizer is pruning that now-unused expression node from its basic block. Root cause: the optimizer's expression-elimination routine switches on the sub-expression's kind to decide how to recurse into its operand before erasing the node, and the branch that is supposed to handle the postfix increment/decrement case mistakenly reinterprets the node through the accessor for the differently-laid-out prefix increment/decrement variant instead of its own type, so it retrieves an unrelated field reinterpreted as an expression pointer rather than the real operand; the very next step, which checks that bogus pointer's own kind so recursion can continue, dereferences it and segfaults on the invalid address.
