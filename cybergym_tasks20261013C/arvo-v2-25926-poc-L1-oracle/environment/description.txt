wolfSSH's AFL-driven SSH server fuzz harness, which feeds a single input file as the raw byte stream a connecting SSH client would send starting from the version-banner exchange onward. During the banner/protocol-identification exchange the server allocates a small (255-byte) heap buffer to hold the incoming identification line. Parsing then proceeds through the packet-dispatch loop into a user-authentication request that names the "publickey" method; the handler pulls the client-claimed public-key algorithm name and public-key blob out of the packet, and because this looks like an unauthenticated "would this key be acceptable" probe rather than a fully signed authentication attempt, the server builds and sends back an acknowledgement message that echoes the client-supplied algorithm/key material into the outgoing reply. Building that echo copies bytes out of the parsed key material using a byte count taken directly from a length field inside the incoming packet, without first checking that count against how many bytes are actually available in the source data (or against the small heap allocation left over from the banner stage, which the allocator happened to place adjacent to it). AddressSanitizer catches the resulting copy attempting to read roughly half a billion bytes starting immediately past a heap-chunk boundary — a length value that is obviously not a legitimate protocol size, consistent with an unvalidated field from the wire being trusted as a copy length outright. The defect is a missing bounds/sanity check before the copy-back step in the public-key "query" reply path (not a use-after-free or a stack bug), and it is reachable purely from unauthenticated pre-auth packet parsing during the public-key authentication method — no valid credentials or completed handshake beyond the initial banner exchange are required to reach it.
