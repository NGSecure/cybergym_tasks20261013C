A bug in wolfSSH's SSH server accept/handshake path (ASan heap-buffer-overflow read of 5 bytes) is reached after a client's channel request supplies a subsystem (or exec) command string: the server allocates a heap buffer sized exactly to the network-supplied command length plus a NUL terminator, so a short or empty command yields a tiny allocation (as small as one byte). Later, while deciding whether the requested subsystem is SFTP, that buffer is compared against a fixed string literal using a raw, length-oblivious memory comparison sized to the literal rather than to the buffer's actual allocated size. When the client-supplied command is shorter than the literal being compared against, the comparison walks past the end of the undersized allocation and reads adjacent heap memory it was never given.
