matio's MATLAB v7.3 (HDF5-backed) reader walks a cell array by dereferencing each stored object reference and recursively re-entering the same per-dataset metadata routine on the referenced dataset. When the referenced dataset carries the library's "empty array" marker, that routine takes the marker's declared dimension value straight from the file as an untrusted array rank, frees the dataset's previously-read dims array, and reallocates it to hold exactly that many size_t elements. It then issues a whole-dataspace read of the dataset back into that same freshly (re)sized buffer using the underlying HDF5 API's "read the full extent" selection for both the source and destination sides. Because the buffer was sized from the declared-rank value pulled out of the file rather than from the referenced dataset's actual element count, a crafted reference target whose real dataspace holds more elements than the declared rank lets the full-extent read write well past the end of the undersized heap allocation, corrupting adjacent heap memory.
