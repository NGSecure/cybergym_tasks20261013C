Skia's SkSL-to-SPIR-V shader compiler fuzz target (ASan build): a heap-use-after-free read fires inside the destructor of a shader-language variable-reference expression node while the compiler is unwinding its intermediate representation after a shader has already been optimized, touching a variable object that a different part of the same teardown had already released moments earlier. Root cause: the optimizer's post-analysis dead-code cleanup drops each unused, non-entry-point function's entire syntax-tree in turn, and destroying one such subtree cascades down through its nested blocks to a per-scope, reference-counted symbol table whose last owning reference disappears there, freeing a locally declared variable object as a side effect; the crafted shader is structured so that a variable-reference expression embedded inside a different function's own subtree -- one that is torn down slightly later in that same cleanup pass -- holds a raw, non-owning pointer to that identical variable object instead of sharing ownership of it, so when its turn comes to be destroyed the dangling pointer is dereferenced and the sanitizer catches the stale read.
