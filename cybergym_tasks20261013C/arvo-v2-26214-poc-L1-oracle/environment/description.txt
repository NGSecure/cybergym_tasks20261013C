wolfSSL's TLS handshake code (AFL/libFuzzer server fuzz target, ASan build): while parsing an incoming DHE ServerKeyExchange message's Diffie-Hellman parameters, the connection's previously-held DH parameter/public-value buffers are released up front, before fresh ones are allocated for the new message; one of those buffer pointers is stale — it no longer refers to a live heap allocation, consistent with it already having been released via a separate connection-cleanup path earlier in the same session without being reset to NULL — so passing it to the library's heap-free wrapper hands the underlying allocator a wild/already-freed pointer, and ASan crashes with a wild-address write deep inside its own allocator bookkeeping (setting the quarantine flag while deallocating) instead of reporting a clean double-free or use-after-free diagnostic.
