FFmpeg's JPEG2000 decoder (ASan build) has a heap-buffer-overflow read while decoding tile-part packet headers for a codestream whose main header carries packed-header data via a PPM (Packed Headers, Main) marker segment. During main-header parsing, the packed-header payload collected from the PPM marker segment(s) is placed into a heap-allocated buffer sized to hold exactly that payload — nothing more. Root cause: once packet decoding begins, for a tile-part that draws its packet headers from this packed-header data, the code reads a 4-byte field straight out of the packed-header stream and treats it, without any validation, as the exact byte length of that tile-part's own packet-header sub-stream; it then creates a fresh bounded reader positioned at the current offset with that attacker-controlled length as its declared size, and separately advances the outer packed-header stream forward by the same length. Because the declared length is never checked against how many bytes are actually still left in the packed-header buffer at that point, a crafted codestream can supply a length far larger than what truly remains — easily arranged when the PPM payload itself is tiny, so the buffer allocated to hold it is correspondingly small (a handful of bytes). Packet decoding for that tile-part then reads its header by peeking a 4-byte big-endian value from the sub-stream reader; because the sub-stream's declared size extends well past the true end of the small heap allocation, this peek dereferences memory past the buffer's boundary, which the sanitizer reports as a heap-buffer-overflow read of 4 bytes immediately past the allocation. Fix: immediately after reading the length field, compare it against the number of bytes actually remaining in the outer packed-header stream and abort with an error if the declared length would exceed what is really available, before ever building the sub-stream reader or skipping past that data — closing the gap between the attacker-controlled length field and the buffer's real, much smaller size.
