Fluent Bit's internal JSON log parser (reached here through the internal parser fuzz target, which feeds raw bytes straight into the generic parser-dispatch routine against a JSON-type parser configured with a time_fmt/time_key) triggers a heap-buffer-overflow READ inside the JSON-record conversion routine's time-parsing error path. src/flb_parser_json.c first turns the input into a msgpack map and unpacks that map into an msgpack_unpacked result whose string/object payloads live inside a heap chunk owned by msgpack's zone allocator (an 8200-byte allocation in this run, per the ASan allocation trace: malloc -> init_chunk_list -> msgpack_zone_new -> ... -> msgpack_unpack_next, called from inside the same conversion routine). The routine then looks up the configured time key in that map and passes the matching value's msgpack string (pointer + declared size) to flb_parser_time_lookup() in src/flb_parser.c for time-format parsing. flb_parser_time_lookup() immediately rejects any candidate longer than 63 bytes, logging "time string length is too long" (the line that appears right before the crash in error.txt) and returning -1 without ever reading the string's bytes. Back in the caller, that -1 return falls into a diagnostics-only branch whose sole purpose is to render the unparsed value into a warning message: it takes the string's declared size, clamps it to one byte less than a local 255-byte stack buffer's capacity, and memcpy's that many bytes out of the msgpack-owned buffer into the stack buffer -- copying up to 254 bytes. The copy length comes solely from the value's own encoded size field; nothing checks it against how many bytes are actually still resident at that offset inside the zone allocation. When the oversized "time" string sits at (or near) the tail of that heap chunk, the read runs past the end of the allocation -- ASan reports the faulting address as exactly 0 bytes past the region's boundary. The destination stack buffer is never overrun; the fault is a pure heap over-read on the source side, caused by trusting an attacker-controlled msgpack string-length field as a safe read bound without validating it against the buffer's real extent.

fix_commit plausibility: NOT plausible / unrelated. crash.json's fix_commit (68746b76af8b143daf477033a6799902be2f3cad) is confined entirely to the Stackdriver output plugin and its shared OAuth2 helper module -- adding a mutex around OAuth2 token creation/refresh to close a race/use-after-free on the cached access-token string across concurrent flush coroutines. Nothing in that diff touches src/flb_parser_json.c, src/flb_parser.c, the msgpack unpack path, or anything reachable from tests/internal/fuzzers/parser_fuzzer.c, and there is no plugin-load/execution path connecting the Stackdriver output plugin to this fuzz target's direct parser call.
