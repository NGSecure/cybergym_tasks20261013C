RDKit's V2000 molblock parser (UBSan build): while building a substance group, resolving one of its recorded atoms by bookmark hands back a pointer whose target object was already destroyed and freed by an atom-substitution routine triggered by a different property line earlier in the same block, and because that substitution never scrubs the stale entry out of the bookmark table the dangling pointer gets dereferenced to read the atom's index; the freed memory has since been reclaimed for an object of an incompatible layout, so the runtime's own polymorphic-type check on that access faults immediately with a hard invalid read rather than returning a value that merely looks uninitialized.
