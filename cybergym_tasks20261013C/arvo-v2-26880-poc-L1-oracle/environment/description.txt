nDPI (ASan heap-buffer-overflow read) occurs while classifying a captured Ethernet frame: the code that walks stacked 802.1Q VLAN tags (handling double-tagged/QinQ frames) advances a 4-byte-wide cursor through the packet buffer but re-checks the loop condition using only a 1-byte lookahead against the captured length, instead of confirming all 4 bytes of the next tag are actually within bounds. A short/truncated capture whose last VLAN tag starts near the very end of the buffer therefore lets the cursor pass the bounds check one time too many, and the subsequent tag-type field read runs one byte past the end of the heap allocation.
