A crafted Garmin JNX map image makes GraphicsMagick's JNX reader extract one of the file's embedded JPEG map tiles and hand it to the bundled libjpeg-turbo decoder as a progressive JPEG; decoding that tile with MemorySanitizer instrumentation reports a use-of-uninitialized-value read inside the decoder's block-smoothing output stage (the code path libjpeg-turbo takes when it renders a partially-decoded progressive scan by interpolating from lower-precision coefficient data instead of waiting for the full scan).

Root cause: for each color component, before doing the actual DCT-block interpolation this stage first inspects a small per-component "how many AC coefficient bits are currently known" bookkeeping array to decide whether only the DC term needs interpolating. That bookkeeping array is really two halves — a "current scan" half and a "previous scan" half — packed into one buffer that libjpeg-turbo's internal small-object pool allocator hands out without zeroing it first. The half describing the *previous* scan's precision is populated by a separate snapshot routine, but only on the condition that the decoder has already advanced past its very first input scan; on the first scan there is by definition no prior scan to snapshot, so that routine deliberately skips writing the "previous scan" half at all, leaving it exactly as the pool allocator handed it out: uninitialized. The block-smoothing stage normally reads the "current scan" half instead, except when it decides the scan it's currently rendering is incomplete (i.e. input stopped making forward progress on this image row before finishing it) — in that situation it deliberately falls back to reading the "previous scan" half so it can smooth using the last fully-known data. For this crafted tile, the progressive scan sequence is arranged (via a truncated/malformed subsequent scan or restart-interval mismatch inside the tile's own JPEG stream, independent of any JNX-specific corruption) so that this fallback condition is reached while still within the very first input scan — at which point the "previous scan" half was never written by anything, and the smoothing stage's bit-array comparison reads and branches on raw, never-initialized heap bytes from that pool allocation.
