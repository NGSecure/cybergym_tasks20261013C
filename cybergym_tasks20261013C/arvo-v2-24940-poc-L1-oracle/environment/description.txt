OpenSC's ASEPCOS smart-card driver (ASan build), exercised through the PKCS#15 fuzz target's bind/select-file path: after a file is selected, the raw FCI-derived security-attribute byte string attached to it is parsed as a sequence of TLV entries, and each of the two variable-length access-condition encodings computes how many bytes it will actually consume as one byte more than what its own preceding length check requires to already be present in the buffer. Because the remaining-length counter that gates the parsing loop is an unsigned integer, once the actual (larger) consumed length is subtracted and it exceeds what is left, the counter underflows to a very large value instead of reaching zero or going negative, so the loop keeps iterating with a cursor that has already advanced one byte past the end of the heap-allocated attribute buffer, and the next iteration's leading two-byte tag comparison performs a one-byte out-of-bounds heap read just past that buffer.
