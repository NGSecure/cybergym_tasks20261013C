One-line summary: While subsetting a font's `cmap` table, HarfBuzz's serializer for the Unicode Variation Sequences (format 14) subtable presses on and reorders its list of per-variation-selector entries even when an internal step that links those entries to their target UVS mapping data has already failed, so the reordering step walks off the end of a table that was never fully written and crashes on a wild address.

Crash mechanism: Subsetting a `cmap` table copies each retained subtable into a fresh output buffer, one copy routine per subtable format. For the Unicode Variation Sequences subtable, this copy first serializes the surviving variation-selector entries and then restores their required ascending order with an in-place array reversal that swaps entries pairwise via assignment. Building the list of already-serialized default/non-default UVS mapping objects that each entry needs to reference uses its own growable internal bookkeeping vector, separate from the main output buffer. When that vector's allocation fails partway through (for example because the subset retains an unusually large number of variation-selector ranges), nothing downstream previously checked for that failure, so the surrounding code kept going as if every entry had been linked up successfully: it still committed the subtable's final byte length and entry count, and it still ran the reversal over the full, nominal number of entries. Because the entry count and length that got committed no longer matched what had actually been written into the output buffer, the reversal indexed and pairwise-copied entries past the buffer's real extent. Since each entry is copied with a fixed-size raw memory copy, the address it computes from those now-bogus bounds falls completely outside any region the allocator or the sanitizer's shadow memory knows about, producing an unrecoverable wild-address segmentation fault rather than an ordinary, bounds-checked heap overflow.

Trigger conditions: the crash requires (a) subsetting a font whose `cmap` table contains a Unicode Variation Sequences subtable with enough retained variation-selector entries that the internal per-entry linking step exhausts memory or otherwise fails partway through, and (b) that failure going unchecked by the surrounding serialization code instead of aborting the subtable — both satisfied by a suitably crafted font fed to the subsetting fuzz target.
