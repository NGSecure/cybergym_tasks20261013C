SELinux's CIL policy compiler (secilc, ASan build) aborts with an 8-byte heap-use-after-free read raised while resolving a type name referenced by an access-vector rule. The crash needs a type declared inside an `optional` block that gets disabled during resolution (for instance because a sibling statement in the same block cannot be resolved), plus a separate construct elsewhere in the policy — such as a parameterized macro invoked with that type as an argument — that is only expanded and resolved on a later pass. Because the disabled block's declarations are torn down immediately rather than being kept around until every later-pass consumer has finished using them, the deferred resolution of that outside reference dereferences a type record that no longer exists.
