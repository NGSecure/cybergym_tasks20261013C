LLVM's opt-fuzzer harness (ASan build) parses a bitcode module and tears down its LLVMContext once the run finishes; that teardown is where the crash occurs. Freeing the context releases a shared per-context bump-pointer arena that backs a variety of long-lived, context-owned objects — among them the attribute objects built while the bitcode reader parses the module's attribute-group block, and the small derived-type objects allocated whenever a new type is interned. A per-type poison-value singleton that the context itself keeps alive is not explicitly released before this arena goes away; it is left to be cleaned up only as an ordinary data member at the very end of the context's destructor, after the arena has already been torn down. Tearing down that lingering poison value runs the normal value-destruction path, which clears its entry in the value-name table — and doing so needs to walk back through the value's type to find the owning context. Because that type object was itself carved out of the arena that was just freed, the lookup dereferences already-freed heap memory, producing the use-after-free read.
