FFmpeg's Vividas (.viv) demuxer (libavformat) has a heap-buffer-overflow (out-of-bounds 4-byte read, flagged by AddressSanitizer) triggered while reading packets back out of a crafted .viv container. Root cause: while parsing the container header, the demuxer sizes an in-memory per-track index/keyframe table from a count value taken directly from the file without validating it against the amount of index data actually present, so for a malformed input the allocated table can end up as small as a single byte; when packets are later pulled from the stream using that table, the code indexes past the end of this undersized buffer.
