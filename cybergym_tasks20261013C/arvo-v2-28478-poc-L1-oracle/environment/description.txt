SELinux's CIL policy compiler (secilc, ASan build) aborts with a 4-byte heap-use-after-free read raised from the diagnostic code path that reports a conflict in a policy-wide ordering statement. The crash needs a security-identifier ordering entry that only exists because it was copied into the policy tree by a block-inheritance statement, coming from a source block that is itself later disabled and torn down during resolution. When the ordering-merge step subsequently detects that this identifier cannot be placed in the requested order and tries to log which policy statement caused the conflict, it reads the tree node for that already-freed, inherited copy in order to describe its location.
