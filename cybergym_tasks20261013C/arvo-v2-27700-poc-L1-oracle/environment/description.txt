PcapPlusPlus's packet-reconstruction path (UBSan build): building a Packet from a raw UDP datagram whose source or destination port matches the well-known DNS port constructs a DNS layer object, whose constructor walks the packet's query/answer/authority/additional resource records in a loop, allocating one record object per entry. Each record's on-wire size is derived from a name that may itself use DNS-message compression (a back-reference to an earlier offset within the same packet) followed immediately by fixed type/class/TTL/length header fields that are read straight out of the raw packet bytes at the offset just past the decoded name, before that offset has been validated against the packet's actual length; only after a record object has already been built and its size computed does the loop compare the resulting cumulative offset to the layer's declared data length. A malformed, undersized UDP payload disguised as a DNS message can therefore place a record's trailing length field past the real end of the allocated packet buffer, so the size derived for that record no longer reflects genuine packet content. That bad bookkeeping carries into later loop iterations and leaves the DNS layer object still being constructed in a state where its own base-class bookkeeping is no longer intact by the time an ordinary member read happens on it: the sanitizer's dynamic-type check finds that the memory the object pointer refers to no longer looks like a valid base-class instance and reports it as a bad-cast (member access through an object whose vtable pointer is invalid).
