uWebSockets HTTP request parsing (MSan build, plain non-proxy chunked fuzz target): a length value derived from the request-line target token is computed with unsigned subtraction and wraps around to a huge value whenever the token is shorter than the fixed suffix being trimmed off it. Unlike a crash that surfaces immediately inside the parser's own scanning loop, here the corrupted length survives into the reconstructed target view that the parser eventually hands back to the caller once request processing completes — its bound is derived from wherever an internal delimiter search gave up, which inherits the same oversized length. The caller-side logic then walks that view one character at a time to force every byte to be touched (this codebase's fuzz harnesses deliberately do this to surface exactly this class of bug under sanitizers), and that walk strides so far past the tiny backing buffer that it lands on unmapped memory, so the fault is reported inside that later read loop rather than inside the parser itself. Reaching this requires the length-prefixed chunked fuzz-input framing used by this particular target, distinct from the raw single-buffer input that trips the more immediate variant of the same underlying defect.
